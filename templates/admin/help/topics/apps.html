An app tells the gateway which Android package or iOS bundle belongs to a product, and which credential delivers to it. Add one app per platform.

Add an app

  1. Apps → Add.
  2. Product: the app family.
  3. Platform: Android or iOS.
  4. Bundle id: exactly as in the store. Android: the package name, e.g. com.sc.boutique (from applicationId). iOS: the bundle identifier from Xcode.
  5. Credential: Android must use a Firebase credential; iOS uses an Apple credential (or Firebase if the app gets its tokens from Firebase on iOS too).
  6. Android channel id (optional): the notification channel used when a send names none, e.g. orders. The app must create that channel; SC Boutique creates orders.
  7. Save.

Things that trip people up

  • Build flavors change the package name. SC Boutique's dev build is com.sc.boutique.dev; only the exact package registered here can register phones.
  • The same bundle id can exist under two products; each product only sees its own.
  • The Firebase project of the credential must contain this Android app (Firebase console → Project settings → Your apps), and the app's google-services.json must come from that same project.
  • For iOS, the Apple key's team must own the bundle id, and Push Notifications must be enabled for it in the Apple Developer portal.

The list shows how many active devices each app has; zero after release means the app is not registering: see Troubleshooting.
