This is the full checklist for giving any new app push notifications, for example a future delivery app. Do it top to bottom. Parts A and B are needed only once ever; skip them if the credentials already exist under Credentials.

schedule
About 30 minutes the first time, 10 minutes for each app after that. You need: the Firebase console, an Apple Developer account (for iOS), this dashboard, and a developer for the app and backend parts.

A. Firebase: once, for all Android apps

  1. Go to console.firebase.google.com → Add project (or open the existing one, e.g. server-push-notification-2adb0). Analytics can be off.
  2. ⚙️ Project settings → Service accounts → Generate new private key → Generate key. A .json file downloads: this is the service account key.
  3. Cloud Messaging tab: check Firebase Cloud Messaging API (V1) is Enabled.
  4. Here: Credentials → Add → name firebase-main, provider Firebase Cloud Messaging → open the JSON file in a text editor, copy all of it, paste → Save.
  5. Save the JSON in your password manager and delete it from Downloads.

B. Apple: once, for all iOS apps

  1. developer.apple.com → Account → Certificates, Identifiers & Profiles → Keys → +.
  2. Name Push Gateway, tick Apple Push Notifications service (APNs) (Sandbox & Production) → Continue → Register.
  3. Download AuthKey_XXXXXXXXXX.p8. ⚠️ Only one download is ever allowed: store it in your password manager now.
  4. Write down the Key ID (10 characters, in the file name) and the Team ID (top right of the developer site, or Membership).
  5. Here: Credentials → Add → name apple-main, provider Apple Push Notification service → Team ID, Key ID, and the whole .p8 text including the BEGIN/END lines → Save.

C. Register the new app with Firebase and Apple

  1. Android: Firebase → Project settings → General → Add app → Android → enter the package name exactly (e.g. com.example.delivery, the applicationId) → Register → download google-services.json and hand it to the app developer.
  2. iOS: Firebase → Add app → iOS → bundle id → download GoogleService-Info.plist for the developer.
  3. iOS: Apple Developer → Identifiers → the app's bundle id → tick Push Notifications → Save.

D. Create the product here

  1. Products → Add → name it (e.g. "Delivery App") → Save.
  2. A yellow box shows secret_key (sk_…), publishable_key (pk_…) and identity_secret. ⚠️ Copy all three into your password manager now; the two keys are never shown again.
  3. Lost them? Open the product → Rotate keys for new ones (old ones stop working), and Show identity secret to see that one again.

E. Add the product's apps

  1. Apps → Add → Product: the new product, Platform: Android, Bundle id: the package name, Credential: firebase-main, Android channel id: the channel the app creates (e.g. orders) → Save.
  2. Again for iOS: Platform iOS, the bundle id, Credential apple-main → Save.
  3. Build flavors with other package names (.dev, .staging) each need their own app row if they should receive pushes.

F. Hand over to developers

WhoGetsWhere it goes
App developergoogle-services.json, GoogleService-Info.plist, the pk_ key, this server's URL The app (Firebase files kept out of git; pk_ and URL in the app's environment file)
Backend developersk_ key, identity secret, this server's URL Backend environment variables PUSH_GATEWAY_SECRET_KEY, PUSH_GATEWAY_IDENTITY_SECRET, PUSH_GATEWAY_URL

Send keys through a password manager share or another private channel, never in group chats or email. Developer details: Connecting a Flutter app and Sending from your backend.

G. Test

  1. Install a build on a real phone, sign in, tap Allow for notifications.
  2. Within a few seconds the phone appears under Devices as Active.
  3. Put the app in the background, then Send test notification → the new product → Send.
  4. The phone buzzes; tapping opens the app. The notification here shows Sent 1/1 and Opened 1.
  5. Nothing arrived? Troubleshooting.

H. Before going live

  • The release build includes the Firebase files and push is switched on in its environment file.
  • Android: status-bar icon is single-colour, the notification channel exists, version code is higher than the last upload.
  • Play Console → Data safety: declare "Device or other IDs: collected, for app functionality".
  • App Store (iOS): Push Notifications capability is on in the release build.
  • The backend sends real events (order ready, reminders) and links users at login.
  • An uptime monitor pings /healthz every 5 minutes (free Render plan).
