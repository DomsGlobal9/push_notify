Pushes reach every user of your apps, so the keys that can send them must never leak. The rule is simple: only the pk_ key may ever be inside an app.

Every secret, where it lives

Built-in protections

  • API keys are stored hashed and shown once; provider keys are encrypted (AES-256-GCM).
  • An app key cannot send, list users or read other phones.
  • Linking a phone to a user needs a token signed by your backend, so nobody can receive another person's pushes.
  • Products are fully separated: a key only reaches its own product's data.
  • Push tokens are never returned by the API.
  • The database tables are locked away from Supabase's public API.
  • Tapped pushes can only open in-app screens, never outside links.
  • Sending is rate limited per product.

Routine

  • Use strong, unique passwords for admin users and remove people who leave.
  • Never paste keys into chats, tickets or screenshots; if you did, rotate them.
  • Do not commit .env files, service account JSON or .p8 files to git.
