Your backend sends by calling the gateway over HTTPS with the product's secret key. The call returns immediately (status 202); delivery happens in the background.

Setup (once per backend)

Environment variableValue
PUSH_GATEWAY_URLThis server's address, e.g. https://push-notify-7upj.onrender.com
PUSH_GATEWAY_SECRET_KEYThe product's sk_… key
PUSH_GATEWAY_IDENTITY_SECRETThe product's identity secret (only needed to link users)

Send

{% verbatim %}
POST /v1/notifications
X-API-Key: sk_...
Idempotency-Key: order-1042-ready        (optional: a retry never sends twice)

{
  "target":  {"user_ids": ["sarala_boutique:12"]},
  "message": {
    "title": "Your order is ready",
    "body": "Pick it up any time after 4 pm",
    "data": {"route": "/orders/1042"},
    "android_channel_id": "orders",
    "priority": "high",
    "ttl_seconds": 86400,
    "collapse_key": "order-1042"
  },
  "send_at": "2026-12-01T04:30:00Z"       (optional: schedule it)
}

Python example

import os, requests

def notify(user_ids, title, body, route=None, key=None):
    requests.post(
        f"{os.environ['PUSH_GATEWAY_URL']}/v1/notifications",
        headers={"X-API-Key": os.environ["PUSH_GATEWAY_SECRET_KEY"],
                 **({"Idempotency-Key": key} if key else {})},
        json={"target": {"user_ids": user_ids},
              "message": {"title": title, "body": body,
                          "data": {"route": route} if route else {}}},
        timeout=10)

Linking users (at login)

import hashlib, hmac, os

def push_identity(tenant_id, user_id):
    push_user_id = f"{tenant_id}:{user_id}"
    token = hmac.new(os.environ["PUSH_GATEWAY_IDENTITY_SECRET"].encode(),
                     push_user_id.encode(), hashlib.sha256).hexdigest()
    return {"push_user_id": push_user_id, "push_user_token": token}
{% endverbatim %}

Return both fields in the login and "who am I" responses; the app passes them to the gateway.

Who to send to: target

FieldReaches
"user_ids": [...]Every active phone linked to those users (up to 10,000 per call)
"topics": [...]Phones subscribed to any of those topics (each phone once)
"installation_ids": [...]Exact installs (handy for testing one phone)
"all": trueEvery active phone of the product
"platforms", "bundle_ids"Optional filters added to any of the above

Use exactly one of the first four.

Message fields

title, bodyWhat people read. Title up to 200 characters.
dataText values given to the app. route = in-app screen to open on tap.
imagePicture URL (Android shows it; iOS needs a notification extension).
priorityhigh (default, wakes the phone) or normal
ttl_secondsGive up if undelivered after this (phone offline). Default 1 day; 0 = now or never.
collapse_keyA newer push with the same key replaces the older one on the phone.
badge, sound, android_channel_id, content_availablePlatform extras

Title, body, data and image together must stay under 3,500 bytes (Telugu, Hindi and similar scripts use 3 bytes per letter).

Other calls

GET /v1/notifications/<id>Status and counts of one send, with recent failures
POST /v1/notifications/<id>/cancelStop a queued or running send
GET /v1/users/<user>/devicesA user's phones
DELETE /v1/users/<user>Delete a user's devices (account deletion)

Answers

Errors always look like {"error": "…", "code": "…"}.

202Queued
200Same Idempotency-Key as an earlier call: the original is returned, nothing new is sent
400Invalid request; details says which field
401Missing or wrong key
403A pk_ key was used to send (only sk_ can)
429Too many sends: 600 per minute per product
